## 1. [전역·최우선] 단계 색상 토큰이 없어 계약·집행이 전부 블루로 보인다

이건 특정 화면 문제가 아니라 전 화면에 걸친 문제라 먼저 정리한다.

**Before (검증한 사실)**
- `theme/tokens.css`에는 블루 계열(`--samsung-blue`, `--blue-step-1/2/3`, `--executed-color: #1428A0`)만 있고 **퍼플·그린 토큰이 없다.**
- 그래서 계약/집행을 표현하는 곳들이 전부 블루로 하드코딩돼 있다:
  - `OrgIntegratedProgressChart.vue`: 품의완료율 `#BAE6FD` / 계약전환율 `#38BDF8` / 집행률 `#1428A0` → **블루 명도 3단계뿐**.
  - `StageFlowChart.vue`: 4개 막대 전부 `#1428A0` 단색.
  - `StatusDetailView.vue`: 계약 서브탭의 `OrgStackedBarChart` "등록" 색 `#1428A0`, 집행 서브탭 "집행금액" 색 `#1428A0`, 계약 라인 `#1428A0`, 집행 라인 `#1428A0`.
  - `StatusDetailView.vue`의 `.sub-tab-btn.active` 배경도 3개 서브탭 모두 `--samsung-blue`.

**Reference**: 이미지 1은 "단계 전환율 요약" 3카드부터 하단 3개 모니터링 섹션까지 **품의=블루 → 계약=퍼플 → 집행=그린**이 일관되게 반복된다. 색의 이동 자체가 "품의 → 계약 → 집행"이라는 시간 흐름을 암시하는 핵심 장치다.

**근거**: 같은 색을 세 단계에 재사용하면 사용자가 "이 숫자가 품의인지 집행인지"를 매번 범례/제목으로 확인해야 한다. 색이 단계를 구분해 주면 인지 부하가 사라진다. 레거시(`web_new5...py`)가 블루 명도 3단계를 쓴 것은 사실이지만, 그건 "시간 흐름을 명도로" 표현한 옛 방식이고, 확정 레퍼런스와 v2 토큰 표는 색상(hue) 3종으로 바꾸도록 되어 있다.

**지시 (frontend-dev)**
- `theme/tokens.css`에 추가:
  ```
  --stage-po-color: #1428A0;      /* 품의 = 기존 samsung-blue 재사용 */
  --stage-contract-color: #7C3AED; /* 계약 = 퍼플 */
  --stage-execution-color: #059669;/* 집행 = 그린 */
  ```
  더불어 각 단계의 "옅은 트랙/보조선"용 톤도 한 벌 정의해 두면 재사용이 쉽다: `--stage-po-soft:#DBEAFE`, `--stage-contract-soft:#EDE9FE`, `--stage-execution-soft:#D1FAE5`.
- **하드코딩 색 문자열을 토큰으로 중앙화**: 지금 `.vue`의 `<script>` 안에 `'#1428A0'`·`'#BAE6FD'`가 직접 박혀 있어 ECharts `option`에서 CSS 변수를 못 읽는다. `src/theme/stageColors.ts` 같은 상수 모듈을 하나 만들어 `STAGE = { po:'#1428A0', contract:'#7C3AED', execution:'#059669' }`로 export하고, 차트들이 이걸 import해서 쓰도록 한다(테마 1곳 수정 → 전 차트 반영).
- 적용 매핑(어느 요소가 어느 단계인지)은 아래 화면별 항목에서 구체화한다.

## 2. 종합현황 탭 (`views/DashboardView.vue`)

### 2-1. "조직별 종합 진행률" 차트 — 블루 3단계 → 블루/퍼플/그린
**Before**: `OrgIntegratedProgressChart.vue`의 3개 series가 `#BAE6FD / #38BDF8 / #1428A0`(블루 명도차)로만 구분된다. 조직이 여러 개면 옅은 블루 3개가 뭉쳐 어느 막대가 계약인지 집행인지 즉시 구분이 안 된다.
**After**: 품의완료율=`--stage-po-color`, 계약전환율=`--stage-contract-color`, 집행률=`--stage-execution-color`. 범례를 안 봐도 색만으로 단계가 읽힌다.
**지시**: `OrgIntegratedProgressChart.vue`의 `itemStyle.color` 3개를 위 매핑으로 교체. 값·축·라벨 로직은 그대로.

### 2-2. "전체 진행 퍼널"(StageFlowChart) — 단계별 색 부여
**Before**: `StageFlowChart.vue`의 막대 4개(전체투자/품의완료/계약등록/집행발생)가 전부 `#1428A0`.
**After**: 전체투자=중립 회색(`--unexecuted-color` 톤), 품의완료=블루, 계약등록=퍼플, 집행발생=그린. 퍼널을 내려갈수록 색이 바뀌어 "단계 이동"이 시각화된다.
**지시**: `StageFlowChart.vue`에서 `series[0].data`를 단일 `itemStyle` 대신 데이터포인트별 색 배열(`itemStyle` per-data 또는 `data:[{value, itemStyle:{color}}]`)로 준다. 매핑은 stage 이름 기준.

### 2-3. "월별 핵심 진행 흐름"(MonthlyComboChart) — 집행 라인은 그린으로
**Before**: `DashboardView.vue`에서 누적품의금액 라인 `#1428A0`, 누적집행금액 라인 `#BAE6FD`(옅은 블루) 점선. 집행이 "옅은 블루"라 품의(진한 블루)의 보조선처럼 보이고, 두 라인이 같은 색 계열이라 겹칠 때 구분이 어렵다.
**After**: 누적품의금액=`--stage-po-color`(블루 실선), 누적집행금액=`--stage-execution-color`(그린 점선). 서로 다른 hue라 겹쳐도 분리돼 읽힌다.
**지시**: `DashboardView.vue`의 `monthlyLines` computed에서 2번째 라인 `color: '#BAE6FD'` → 그린 토큰으로. 배경 막대(계약건수)는 중립 회색 유지.

### 2-4. 상단 KPI 6칸 — 레퍼런스보다 살짝 무겁다 (경미)
**Before**: `MiniKpiGrid`가 라벨+값 아래 항상 `caption`을 깔고, tone별 컬러 테두리(good/warn/bad)를 준다. `min-height: 7rem`.
**Reference**: 이미지 1 최상단 KPI 6칸은 라벨+값만 있고 캡션·컬러 테두리가 없어 훨씬 가볍다. 캡션/톤 강조는 그 아래 "단계 전환율 요약"과 하단 섹션이 담당한다.
**근거**: 상단 KPI는 "숫자를 빠르게 훑는" 영역이라 정보 밀도를 낮추는 게 스캔 속도에 유리하다. 다만 캡션은 계산식(예: "기성처리금액/품의금액") 근거를 주는 실용적 가치가 있어 완전히 없앨 필요는 없다.
**지시(선택)**: `MiniKpiGrid`에 `dense?: boolean` prop 추가. dense일 때 caption 숨김 + `min-height` 축소 + tone 테두리 대신 **관리필요/위험 카드만** 좌측 4px 컬러 바로 강조. 종합현황 최상단 6칸에만 `dense`를 적용하고, 상세 탭의 8칸/서브 KPI는 지금처럼 캡션 유지.

### 2-5. 탭 바 스타일 — 밑줄 탭 vs 필 탭 (경미)
**Before**: `App.vue` `.tab-btn`이 `border-bottom: 3px` 밑줄 탭.
**Reference**: 이미지 1 상단 탭("투자 종합현황 / 투자 진행 상세현황")은 **라운드 필(pill) 세그먼트**이고 선택 탭에 옅은 블루 배경(`--stage-po-soft` 계열)이 깔린다.
**지시(선택)**: `.tab-btn`을 필 형태(`border-radius`, 선택 시 옅은 블루 배경 + `--stage-po-color` 텍스트)로 변경. 기능 영향 없음. 우선순위 낮음.

## 3. 진행 상세현황 탭 (`views/StatusDetailView.vue`) — 레퍼런스 이미지 1의 실제 화면

레퍼런스 이미지 1이 바로 이 탭이다. 그래서 이 탭이 레퍼런스와의 격차가 가장 크다.

### 3-1. [핵심] "단계별 진행 전환 흐름"을 3장의 StageFunnelCard로
**Before**: `StageFlowChart.vue`(가로 막대 4개) 하나로 퍼널을 보여준다. 전환율(품의완료율/계약전환율/집행발생률)은 상단 `MiniKpiGrid` 텍스트로만 존재한다.
**Reference**: 이미지 1 "단계 전환율 요약"은 3개 독립 카드다. 각 카드 = (a) 단계명("품의 대상 → 품의 완료"), (b) **초대형 퍼센트**(단계색), (c) 우측 상단 분수 라벨("25/34건"), (d) 하단에 단계색으로 채운 굵은 진행바.
**근거**: 현재 `StageFlowChart`는 "전체(34건) 대비 비율"만 준다. 그래서 `계약등록 18건`이 전체의 52.9%라는 것만 읽히고, **"품의완료 25건 중 72%가 계약까지 넘어갔다"는 단계 간 전환율은 못 읽는다.** 어느 단계에서 이탈이 큰지 짚으려면 후자가 필요하다. 카드형은 이 전환율을 분리해 크게 보여준다.
**지시**
- 신규 `frontend/src/components/charts/StageFunnelCard.vue`(순수 CSS/SVG, 차트 라이브러리 불필요). props: `{ label:string, rate:number, numerator:number, denominator:number, color:string }`.
- `StatusDetailView.vue`의 "단계별 진행 전환 흐름" 자리를 카드 3장으로 교체(또는 병행): 품의완료율(`overview_kpi.po_completion_rate`, `po_done_count/total_count`, 블루), 계약전환율(`contract_conversion_rate`, `contract_count/po_done_count`, 퍼플), 집행발생률(`execution_conversion_rate`, `executed_count/contract_count`, 그린). 이 값은 이미 `overview_kpi`(BE `make_stage_summary`)에 전부 있어 **백엔드 변경 없이** 붙는다.
- **>100% 처리(목업엔 없던 보완점)**: 집행발생률처럼 100%를 넘는 경우(예 138.9%), 진행바를 100%에서 자르면 "가득 참"으로 보여 초과 정보가 사라진다. 초과분은 (1) 채움 끝에 얇은 대각선 스트라이프/화살촉으로 "100%+"를 표시하거나, (2) 최소한 퍼센트 숫자만 단계색으로 크게 두고 바는 100%로 두되 분수 라벨(25/18건)이 초과를 설명하도록 둔다. 목업은 (2)로 그려 뒀으니, 여유가 되면 (1)까지 얹는 걸 권장.
- 종합현황 탭 "전체 진행 퍼널" 자리에도 축소판으로 재사용 가능.
- 목업: `docs/design-review/mockups/stage-funnel-card.html`

### 3-2. [핵심] 서브탭(품의/계약/집행)을 단계색으로 코딩
**Before**: `.sub-tab-btn.active` 배경이 3개 모두 `--samsung-blue`. 어느 단계를 보고 있는지 색으로 구분이 안 된다.
**After**: 품의 서브탭 선택색=블루, 계약=퍼플, 집행=그린. 아래 차트들이 같은 단계색으로 물들면, 서브탭 색 = 섹션 색이 일치해 "지금 계약 화면"이라는 게 한눈에 잡힌다.
**지시**: `.sub-tab-btn.active`에 활성 탭 키별 색 클래스(`.active.po/.contract/.execution`) 부여. 각 서브탭 내부 차트 색도 3-3~3-5대로 맞춘다.

### 3-3. 품의 서브탭 — 조직별 막대를 InlineRatioBar로 (블루)
**Before**: `OrgStackedBarChart.vue`(완료 진한색 + 미완료 연회색 스택). 라벨은 각 세그먼트 안에.
**Reference**: 이미지 1 "조직별 품의완료 건수"는 **하나의 연회색 트랙에 완료 비율만큼 블루로 채운 진행바** + 채움 안 "완료 9건" + 트랙 밖 오른쪽 전체건수("12건"). 스택이 아니라 progress bar다.
**근거**: 실무자가 궁금한 건 "완료/미완료 두 값"이 아니라 "완료가 전체의 얼마인지"라는 비율이다. 트랙+채움은 "미완료" 라벨 없이도 연회색 여백이 자동으로 "남은 부분"으로 읽혀 정보 밀도는 낮추면서 가독성은 올린다. 이미 `DetailTable.vue`의 집행률 progress-cell이 같은 패턴을 쓰고 있으니 시각 언어를 차트 레벨로 확장하는 것뿐이다.
**지시**
- 신규 `frontend/src/components/charts/InlineRatioBar.vue`(순수 CSS). props: `{ label, filled, total, unit, color }`. 트랙 `div` + 채움 `div`(width=filled/total) + 채움 안 라벨 `span` + 트랙 밖 오른쪽 총량 `span`.
- **좁은 채움 폴백(목업에 반영한 보완점)**: 완료 비율이 낮으면(예 14%) 채움 안 흰 글씨가 잘린다. 채움 폭이 라벨보다 좁을 때는 라벨을 채움 **바깥(연회색 트랙 위)**에 진한 회색으로 배치해야 한다. 목업 4번째 행(`데이터_PJT`)에 이 폴백을 그려 뒀다.
- 적용: `StatusDetailView.vue` "조직별 품의완료 건수"(`po_monitoring.org_table`: `completed/total`, 블루). 지금 `OrgStackedBarChart` 자리를 `InlineRatioBar` 반복으로 교체.
- 목업: `docs/design-review/mockups/inline-ratio-bar.html`

### 3-4. 계약 서브탭 — 전부 퍼플로
**Before**: 조직별 계약건수 `OrgStackedBarChart` "등록" 색 `#1428A0`(블루), 월별 라인 누적계약건수 `#1428A0`(블루).
**After**: "조직별 계약건수"도 `InlineRatioBar`(등록/전체, **퍼플**), 월별 누적계약건수 라인 퍼플, 보조 누적품의완료건수 라인은 옅은 블루 점선 유지(전 단계 참조선). 서브탭 색과 통일.
**지시**: `StatusDetailView.vue` 계약 블록의 색 문자열을 퍼플 토큰으로. `OrgStackedBarChart` → `InlineRatioBar`(`registered/total`).

### 3-5. 집행 서브탭 — 전부 그린으로
**Before**: 조직별 집행금액 `OrgStackedBarChart` "집행금액" 색 `#1428A0`, 월별 누적집행률 라인 `#1428A0`.
**After**: 집행금액은 **집행/미집행 두 금액을 다 봐야 하므로 스택 막대 유지가 맞다**(여긴 InlineRatioBar로 바꾸지 않음). 단 채움 색을 그린으로. 월별 누적집행률 라인도 그린.
**근거**: 품의완료/계약등록은 "완료 건수 대 전체"라 단일 트랙이 자연스럽지만, 집행은 "집행금액 대 미집행금액"이라는 두 금액의 대비가 관리 포인트라 스택이 정보를 더 준다. 이미지 3(프레젠테이션)이 집행을 단일 바로 그린 건 "원거리 요약용"이라 목적이 다르다.
**지시**: 집행 블록 색 문자열을 그린 토큰으로. 막대 구조(스택)는 유지.

### 3-6. 월별 콤보 차트 라벨 — "전 구간 라벨" vs "끝값 콜아웃" 절충
**Before/맥락**: 직전 라운드에서 사용자가 "막대·꺾은선에 값이 적혔으면 좋겠다"고 명시 요청해 `MonthlyComboChart.vue`가 **모든 포인트**에 라벨을 단다.
**Reference**: 이미지 1 "월별 누적 품의금액"은 개별 라벨 없이 **선 끝에만** "최종 120.7" 콜아웃 하나. 훨씬 깨끗하다.
**근거**: 두 요구가 상충한다. 되돌리자는 게 아니라 절충: 중간 포인트 라벨은 유지하되 크기를 줄이고 옅은 색(`--text-subtle`)으로 낮추고, **마지막 포인트만** 진한 단계색+굵게 + "최종" 접두. 사용자의 명시 요청을 훼손하지 않으면서 레퍼런스의 깨끗함을 일부 가져온다.
**지시(우선순위 낮음, 사용자 확인 후)**: `MonthlyComboChart.vue`에 `emphasizeLast?: boolean` prop 추가 — 마지막 인덱스만 `fontWeight`/색/`최종` 프리픽스 다르게. 임의 적용 말고 다음 리뷰에서 A/B 스크린샷으로 결정.

## 4. [범위 큰 항목] 다크 프레젠테이션 모드(`/present`)가 아직 없다

**Before**: 현재는 라이트 업무 화면만 있다(`tokens.css`가 라이트 전용, `App.vue`에 다크 라우트/토글 없음, `activeTab` state로 탭만 전환). v2 2.2절이 계획한 `PresentationBigStat/PresentationBarBoard`와 `/present` 라우트는 미착수.
**Reference**: 이미지 2·3은 **보는 거리와 목적이 다른 화면**(회의실 모니터·현황판, 원거리에서 큰 숫자만 읽음)이다 — 순검정 배경, 초대형 손글씨풍 폰트, 두꺼운 스무딩 라인, 시작점만 원형 마커, 축 라벨 최소(`1월 … 11월`), 색은 블루/그린 2색만. 리스트도 막대 안에 라벨을 넣지 않고 조직명·숫자를 막대 위에 크게, 막대는 단순 진행바. 라이트 컴포넌트를 재사용하면 안 되고 별도 세트가 필요하다.
**근거**: 새 제안이 아니라 계획서 v2에 이미 있던 항목의 착수 시점을 짚는 것. "1단계에선 핵심 위젯 1~2종(조직별 집행금액 바, 누적 집행률)만 다크로 우선"이라는 v2의 축소 범위를 그대로 따르면 된다.
**지시(별도 라운드 권장 — 범위/일정만 참고)**
- `tokens.css`에 다크 토큰 세트: `--present-bg:#0B0B0F`, `--present-text:#EDEDF0`, `--present-muted:#9A9AA3`, `--present-track:#26262B`, 프레젠테이션용 밝은 액센트 `--present-blue:#5B8DEF`, `--present-green:#46B15D`(주의: 업무용 `#1428A0`/`#059669`는 검정 배경에서 너무 어두워 그대로 쓰면 안 보인다 — 프레젠테이션 전용으로 밝기를 올린 값을 별도로 둘 것).
- 신규 `components/presentation/`: `PresentationBigStat.vue`(좌상단 "8억"/"42.5%" 대형 지표 + 컬러 틱), `PresentationLineChart.vue`(스무딩 라인 2개 + 시작점 원형 마커 + 축 최소 라벨), `PresentationBarBoard.vue`(조직별 대형 막대 리스트).
- 라우팅: 지금은 `vue-router`가 없다(`App.vue`가 state 기반). `/present` 진입은 (a) `vue-router` 도입 또는 (b) `window.location.pathname` 최소 분기 중 택1 — pm-coordinator와 사전 조율.
- 목업: `docs/design-review/mockups/presentation-mode.html` (이미지 2 라인 + 이미지 3 바보드를 한 파일에 정적 재현).
