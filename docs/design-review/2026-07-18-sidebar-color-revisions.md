## 1. 사이드바 필터 버튼 개선 계획

### 1-1. 현재 구현과 레거시의 구조적 차이

**현재 구현** (`frontend/src/components/layout/SidebarFilters.vue` + `frontend/src/App.vue` L12~15)
- `SidebarFilters`가 `.page-body`의 **flex 아이템**으로 상시 존재한다(열림 220px / 접힘 44px).
- 접힘 상태에서도 44px 폭을 레이아웃 흐름에서 계속 점유하고, 여는 토글이 사이드바 내부의 **전폭 텍스트 버튼**이다.
- 접힘 시 라벨이 `writing-mode: vertical-rl`로 세로쓰기된 "필터 ›" (SidebarFilters.vue L92~94) — 세로 텍스트는 판독성이 낮고 고급스러운 인상과 거리가 있다.
- 열고 닫을 때 `width`가 220↔44px로 바뀌므로 **본문(`.main-content`) 폭이 함께 리플로우**된다. 사용자가 지적한 "접었다 펴면 본문이 밀린다"의 원인.

**레거시 Streamlit** (`legacy/web_new5_transfer_minus_detail.py`, `sidebar_state="collapsed"`)
- 화면 **좌상단 고정 위치**에 작은 화살표 아이콘(`>>` / `<<`)만 떠 있고, 클릭하면 사이드바가 **그 자리에서 오버레이로 펼쳐진다**. 본문 그리드는 밀리지 않는다.

**레퍼런스 이미지 1**에는 사이드바가 아예 보이지 않는다 — 필터 UI를 화면에서 숨기고 본문을 풀폭으로 쓰는 방향이 레퍼런스의 감각과도 일치한다. 즉 "필터는 평소엔 눈에 띄지 않는 진입점으로만 존재하고, 필요할 때만 오버레이로 불러온다"가 이 대시보드에 맞는 패턴이다.

### 1-2. 결론: flex-push 방식 → 고정 트리거 + 오버레이 드로어 방식

| 방식 | 본문 리플로우 | 레거시/레퍼런스 부합 | "있어보임" | 판단 |
|---|---|---|---|---|
| 현재 flex-push (220↔44px) | **발생(밀림)** | 낮음 | 낮음(세로 텍스트) | 교체 |
| **고정 트리거(FAB) + 오버레이 드로어** | **없음** | 높음 | 높음 | **채택 권장** |

**권장 근거**: 오버레이 드로어는 (1) 본문 폭을 절대 건드리지 않아 사용자가 지적한 밀림 현상을 근본 제거하고, (2) 레거시의 "그 자리에서 열린다" 경험을 재현하며, (3) 레퍼런스처럼 평소 화면을 깔끔하게 유지한다. 실무 대시보드에서 필터는 "가끔 조정하는 보조 컨트롤"이므로 상시 컬럼을 내줄 필요가 없다.

### 1-3. 구체 스펙

**(A) 고정 트리거 버튼 (FAB, floating action button)**
- 형태: 지름 **40~44px 원형** 아이콘 버튼. "필터"라는 **텍스트 라벨은 제거**하고 아이콘만 사용(사용자 요구).
- 아이콘: **sliders / adjustments 아이콘**(가로 3줄 + 노브)을 권장. 깔때기(funnel)보다 "설정/조정" 뉘앙스가 세련되고, 필터 이상의 확장(정렬 등)에도 자연스럽다. 24px, `stroke: currentColor`, stroke-width 1.75, 인라인 SVG.
- 배치 좌표: 본문 최대폭이 1660px 중앙정렬(`App.vue .page`)이므로, 트리거는 **콘텐츠 좌측 상단 모서리에 고정**한다. 권장값:
  - `position: fixed; top: 1.5rem; left: max(1rem, calc((100vw - 1660px) / 2 - 3.25rem));`
  - 넓은 화면에서는 본문 왼쪽 여백(gutter)에 떠 있고, 좁은 화면에서는 `1rem`로 폴백 → 어떤 폭에서도 본문을 가리지 않는다.
  - (구현 단순화 대안: `top: 1.25rem; left: 1.25rem` 뷰포트 고정. 정렬은 덜 정교하지만 훨씬 단순.)
- **"있어보이게" 디테일**:
  - 기본: `background: var(--card-bg); border: 1px solid var(--border-color);` + **떠 있는 그림자** `box-shadow: 0 4px 12px rgba(15,23,42,0.10)` (카드 기본 그림자 `--shadow`보다 깊게 주어 "부유" 느낌).
  - 아이콘 색: 평소 `var(--text-muted)`, hover 시 `var(--stage-po-color)`.
  - hover: `transform: translateY(-1px)` + 그림자 `0 6px 16px rgba(15,23,42,0.14)`, `transition: 150ms ease`.
  - 열림(active) 상태: `background: var(--stage-po-soft); color: var(--stage-po-color); border-color: transparent;` (탭 active 스타일과 언어 통일 — `App.vue`의 `.tab-btn.active`가 이미 `--stage-po-soft` 사용).
  - **활성 필터 개수 배지**(선택, 강력 추천): 우상단에 작은 원형 배지 `background: var(--stage-po-color); color:#fff; font-size:0.65rem`로 현재 걸린 필터 수 표시 → 필터가 숨겨져 있어도 "지금 뭔가 걸려있다"를 알 수 있어 실무 사용성 상승.

**(B) 오버레이 드로어(열렸을 때)**
- 방식: 좌측에서 슬라이드-인하는 **fixed 오버레이 패널**(본문 위에 뜨고, 본문은 밀지 않음).
- 크기/모양: `position: fixed; top:0; left:0; width: 264px; height: 100vh; overflow-y: auto;` + 우측 상단만 라운드 `border-radius: 0 1rem 1rem 0;` + 강한 그림자 `box-shadow: 0 8px 30px rgba(15,23,42,0.16)`.
- 진입 트랜지션: `transform: translateX(-100%) → translateX(0)`, `220ms cubic-bezier(0.4,0,0.2,1)`. 닫힘은 역방향.
- 헤더: "공통 필터" 제목 + 우측 닫기 `×` 버튼(드로어 내부에서도 닫을 수 있게).
- 스크림(dim): 데스크톱에서는 스크림 없이 클릭-아웃(패널 밖 클릭 시 닫힘)만, 모바일 폭(<760px)에서는 반투명 스크림 `rgba(15,23,42,0.28)` 추가 권장.
- 내부 필터 UI(그룹/옵션 버튼/전체·해제/선택 카운트)는 **현재 마크업 그대로 재사용** — 로직 변경 없음.

## 2. 품의/계약/집행 색상 체계 종합 재검토

### 2-1. 문제 정의(사용자 지적 + 코드 확인)

- `frontend/src/components/charts/MonthlyComboChart.vue` L57: 막대 시리즈가 `itemStyle: { color: '#E2E8F0' }`로 **중립 회색 하드코딩**. 어떤 지표든 항상 회색.
- 라인 시리즈는 호출부에서 STAGE 색을 명시(L70~71).
- 그 결과 **같은 화면·같은 차트에서 "계약건수"를 나타내는 막대(회색)와 라인(퍼플)의 색이 다르다** — `StatusDetailView.vue` L124~148 "월별 누적 계약건수" 차트(막대 `월별 계약건수`=회색, 라인 `누적 계약건수`=`STAGE.contract` 퍼플).
- 반면 `DashboardView.vue` L34~42 "월별 핵심 진행 흐름"에서는 막대(`월별 계약건수`, 우축)와 라인(`누적 품의금액`/`누적 집행금액`, 좌축)이 **서로 다른 지표**다.

**핵심 관찰**: 레퍼런스 이미지 1의 콤보 차트도 "연한 배경 막대 + 컬러 라인" 패턴을 그대로 쓴다. 즉 중립 배경 막대 자체는 잘못된 패턴이 아니다. **문제는 막대와 라인이 "같은 지표"일 때 색이 갈리는 경우**뿐이다.

### 2-2. 안 A — 새로운 색상 아이디어(대체 팔레트)

> ⚠️ 프로젝트 가드레일(블루/퍼플/그린 유지)을 벗어나는 탐색안이다. **오너 승인 없이는 적용하지 않는다.** 아래는 색상 이론적 근거와 함께 "만약 새로 짠다면"의 선택지로 제시한다.

**현행 팔레트의 약점(재무 대시보드 관점)**
1. **CVD(색약) 취약**: 품의 블루(`#1428A0`)와 계약 퍼플(`#7C3AED`)은 색상환에서 인접하고, 퍼플은 적록색약에서 적색 성분이 빠지며 **블루 쪽으로 수렴** → 두 단계가 구분이 어려워진다.
2. **다크 프레젠테이션 미대응**: `#1428A0`은 명도가 매우 낮아 **검정 배경(이미지 2·3)에서 거의 보이지 않는다**(실제로 레퍼런스 다크 라인은 더 밝은 블루를 쓴다). 라이트 단일 팔레트로는 프레젠테이션 모드 가독성이 무너진다.
3. **경고색 예약 충돌**: 이 시스템은 이미 `--tone-warn`(앰버) / `--tone-bad`(레드)를 상태 경고로 예약 중이다. 따라서 3단계에 오렌지·레드 계열을 넣으면 "경고"로 오인된다 → **오렌지/레드는 3단계 후보에서 제외**해야 한다. 이 제약 때문에 블루/퍼플/그린 삼색은 사실상 거의 최적에 가깝다(중요한 결론).

**A-1 (권장, 카테고리형 · CVD/다크 튜닝):** 색상(hue)은 유지하되 **명도를 계단식으로 벌리고 테마별 이중값**을 둔다.

| 단계 | 라이트 테마 | 다크(프레젠테이션) 테마 | 소프트(막대/배경) |
|---|---|---|---|
| 품의 | `#1D4ED8` (Blue-700) | `#60A5FA` | `#DBEAFE` |
| 계약 | `#7C3AED` (Violet-600) | `#A78BFA` | `#EDE9FE` |
| 집행 | `#059669` (Emerald-600) | `#34D399` | `#D1FAE5` |

- 품의를 `#1428A0`→`#1D4ED8`로 살짝 밝혀 흰 배경 판독성↑, 퍼플·그린과 **명도 격차 확보**(그레이스케일/CVD에서도 3단 분리). 다크 열은 검정 배경 대비를 위한 밝은 변형 — 이미지 2·3의 감각과 직접 부합.
- 이점: 삼색 정체성 유지 + CVD 개선 + 다크 대응. 사실상 "현행을 유지하며 결함만 제거"에 가까워, **안 B와 자연스럽게 합쳐진다**.

**A-2 (참고, 순차형 "완료 히트" 램프):** 품의→계약→집행을 무관한 3색이 아니라 **쿨→그린 진행 램프**로 인코딩.

| 단계 | HEX |
|---|---|
| 품의 | `#2563EB` (blue) |
| 계약 | `#0D9488` (teal) |
| 집행 | `#16A34A` (green) |

- 왼→오른쪽으로 "차가움=초기, 초록=완료"가 직관적으로 읽힌다(집행=green=돈 집행 완료 은유). 단점: **계약(teal)/집행(green) 인접**으로 두 단계 구분이 A-1보다 약함. 그래서 참고안으로만 둔다.

### 2-3. 안 B — 기존 화면 개선 아이디어(블루/퍼플/그린 유지)

핵심은 **"막대와 라인이 같은 지표인가?"를 기준으로 막대 색을 결정**하는 원칙을 세우는 것.

**중립 회색 배경 막대 vs 단계색 막대 — 언제 무엇을 쓰나 (원칙)**
- **중립 소프트 막대가 정당한 경우**: 막대가 라인과 **다른 지표/다른 축**의 "배경 컨텍스트 크기"일 때. 라인이 주인공, 막대는 규모감만 주는 조연. → 예: `DashboardView.vue` "월별 핵심 진행 흐름"(막대=월별 계약건수, 라인=누적 품의/집행금액, 서로 다른 지표). **현행 회색 유지가 정당**하며 레퍼런스 이미지 1 패턴과 동일.
- **단계색(soft) 막대를 써야 하는 경우**: 막대가 라인과 **같은 단계/같은 지표**일 때. 이때 회색은 "단계 색 언어"를 깨뜨린다. → 예: `StatusDetailView.vue` "월별 누적 계약건수"(막대=월별 계약건수, 라인=누적 계약건수, **동일 지표**). 막대를 **계약-soft(`#EDE9FE`)** 로, 그 위 라인을 진한 `#7C3AED`로 두어 "옅은 톤=월별, 진한 톤=누적"의 **명도 위계**로 계약 스토리를 한 색 계열로 통일.

**구현 방식**: `MonthlyComboChart.vue`에 **선택적 `barColor`(또는 `barStage`) prop 추가**.
- 미지정 시 기본값은 현행 중립 `#E2E8F0`(=컨텍스트 막대, 하위호환).
- 동일 지표 차트에서는 호출부가 stage-soft 값을 넘김.
- 막대 라벨 색(현재 `#475569`, L60)은 soft 막대 위에서 대비가 충분하므로 유지하되, 필요 시 해당 단계의 진한색으로 조정 가능.

**추가 미세 개선**: 레퍼런스 이미지 1의 배경 막대는 순수 회색이 아니라 아주 옅은 라벤더/틴트에 가깝다. 컨텍스트 막대라도 `#E2E8F0`(파랑기 없는 슬레이트) 대신 **해당 화면 주단계의 아주 옅은 soft 틴트**를 쓰면 차트 전체가 한 색 가족으로 묶여 더 정돈돼 보인다(선택).

### 2-5. 추천

**안 B를 1차 채택 권장**하고, **안 A-1의 다크 대응·명도 튜닝만 별도 다크 테마 오버라이드로 흡수**하는 조합을 추천한다.

이유: 사용자는 "편하고 직관적인 느낌"을 원한다. (1) 안 B는 이미 익숙한 블루/퍼플/그린 멘탈 모델을 그대로 두면서 사용자가 실제로 지적한 "같은 지표인데 막대·라인 색이 다른" 불일치만 정확히 제거한다 — 학습비용 0, 즉시 직관성 개선. (2) 레퍼런스 이미지 1과도 정확히 일치한다. (3) 프로젝트 가드레일(색 코드 유지)도 지킨다. ## 3. 추가 UI 개선 제안 (사용자 미요청 · 발견 사항)

검토 과정에서 함께 눈에 띈 항목들. 우선순위 낮음, 참고용.

1. **다크 프레젠테이션 가독성(결함성)**: `#1428A0`은 검정 배경에서 사실상 비가시. 프레젠테이션 모드 도입 시 위 A-1 다크값을 반드시 적용. (근거: 레퍼런스 이미지 2·3.)
2. **타이포 위계 강화**: 현재 `.big-title` 2.4rem(`tokens.css` L53). 레퍼런스 이미지 1의 타이틀 존재감·레거시 3.0rem 대비 다소 약함. 2.6~2.8rem + `letter-spacing` 미세 조정으로 "실무+임팩트" 균형 검토.
3. **진행바 라벨 오버레이 일관성**: 레퍼런스는 채움 안에 값("완료 9건"), 총계는 트랙 밖 우측("12건"). `InlineRatioBar`가 이 패턴을 따르는지 재확인(로드테이블 의제 #3 연계).
4. **콤보 차트 끝값 "최종" 콜아웃**: 레퍼런스 이미지 1의 "최종 120.7 / 최종 18.0 / 최종 42.5"처럼 라인 마지막 non-null 지점을 강조 라벨로. (로드테이블 의제 #4 재확인.)
5. **색 이외 단서(접근성)**: 블루/퍼플은 CVD 취약 쌍이므로, 라인은 이미 dash로 구분하듯 **범례 마커 형태(원/사각/삼각) 차등**이나 아이콘 병기를 추가하면 색에만 의존하지 않아 안전.
6. **신규 FAB/드로어 접근성**: `aria-expanded`/`aria-controls`, `Esc` 닫기, focus-trap, `prefers-reduced-motion` 대응(1-4에 포함).
7. **여백/카드 패딩 일관화**: 레퍼런스 KPI 카드는 테두리를 최소화하고 여백을 넉넉히 쓴다. 카드 border를 옅게(또는 그림자 위주로) 정리하면 더 정돈된 인상.
