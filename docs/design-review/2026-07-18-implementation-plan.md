## 0. 사전 코드 확인 결과 요약

원문 리뷰 문서 작성 시점과 현재 코드가 대체로 일치함을 확인했다. 주요 확인 사항:

- `SidebarFilters.vue`: 리뷰 문서 지목대로 `.sidebar`(L59~70 폭 220/44px 애니메이션), `.toggle-collapsed-label`(L92~94, `writing-mode: vertical-rl`), 전폭 텍스트 토글 버튼(L3~6) 모두 현재 코드에 그대로 존재. 필터 그룹 마크업(L9~33)은 로직 변경 없이 재사용 가능.
- `App.vue`: `.page-body { display:flex; gap:1.5rem; align-items:flex-start }`(L71~75), `<SidebarFilters v-model:open="sidebarOpen" />`가 flex 첫 자식(L13) — 리뷰 문서 서술과 일치.
- `stageColors.ts` / `tokens.css`: `STAGE`/`--stage-*` 라이트 값 리터럴이 서로 정확히 동기화되어 있음(둘 다 po `#1428A0`, contract `#7C3AED`, execution `#059669`). **다크 변수 세트는 전혀 없음**(리뷰 문서의 전제와 일치, 재확인 완료).
- `MonthlyComboChart.vue`: L57 `itemStyle: { color: '#E2E8F0' }` 하드코딩, `barColor` prop 없음(L19~27) — 리뷰 문서 지목과 일치.
- `StatusDetailView.vue`: "월별 누적 계약건수" 콤보차트가 현재 코드 기준 대략 L123~150 구간(막대=`월별 계약건수`, 라인1=`누적 계약건수`(STAGE.contract), 라인2=`누적 품의완료건수`(STAGE.po, dashed)) — 리뷰 문서가 지목한 위치와 정확히 일치.
- `DashboardView.vue`: "월별 핵심 진행 흐름" 콤보차트(L34~44, 막대=`월별 계약건수`, 라인1=`누적 품의금액`, 라인2=`누적 집행금액`) — 리뷰 문서 서술과 일치, 서로 다른 지표.

**새로 확인해 리뷰 문서에 없던 판단이 필요했던 지점**(아래 1-2, 2-2 상세 참고):
- `StatusDetailView.vue`의 품의/집행 상세 콤보차트 2곳을 직접 열어 "동일 지표 여부"를 판정함 — 결론: **둘 다 변경 대상 아님**(2-2절 참고).
- 코드베이스 전체에 `z-index`, `@media`, `position: fixed`가 **단 한 곳도 없음**을 확인(sticky는 테이블 헤더 3곳에만 존재). 즉 이번 작업이 이 프로젝트 최초의 z-index/반응형/fixed 오버레이 도입이다 — 리스크 섹션에서 별도 강조.
- `#E2E8F0` 리터럴이 `MonthlyComboChart.vue`(L57) 외에 `StatusDetailView.vue` L172(`OrgStackedBarChart`의 '미집행' 시리즈 색)에도 하드코딩되어 있음을 확인. 이는 이번 채택 범위(섹션1,2) 밖의 컴포넌트라 수정 대상은 아니지만 리스크로 기록.

## 0-1. 오너 확정 사항 (2026-07-18)

- **활성 필터 배지 기준**: 옵션 단위가 아닌 **그룹 단위**로 카운트한다 — 5개 필터 그룹(조직/계획구분/품의완료/팀장심의의견/센터장심의필요) 중 "전체 선택이 아닌" 그룹의 개수를 배지 숫자로 표시한다(2-1절 배지 로직 확정).
- **집행 상세 콤보차트 barColor**: 리뷰 문서 판단대로 **회색 유지**(변경 없음)로 확정. 3-9절 오픈 이슈는 종결.
- **focus-trap 구현 수준**: **최소 구현**(첫 포커스 이동 + Esc 닫힘 + 트리거로 포커스 복귀)으로 확정. 완전한 Tab 순환 가두기는 이번 라운드 범위에서 제외(3-5절 대안 채택).

## 1. 작업 순서(단계별)

리뷰 문서가 제안한 "사이드바 먼저 → 브라우저 확인 → 색상 진행" 순서를 그대로 채택한다. 두 작업은 서로 다른 파일 집합(사이드바: `SidebarFilters.vue`/`App.vue`, 색상: `stageColors.ts`/`tokens.css`/`MonthlyComboChart.vue`/`StatusDetailView.vue`)을 건드려 코드 충돌 위험은 낮지만, **사이드바 쪽이 이 프로젝트 최초의 fixed/z-index/반응형 도입**이라 검증 부담이 크므로 먼저 단독으로 끝내고 눈으로 확인한 뒤 색상 작업으로 넘어가는 편이 안전하다.

**Phase 1 — 사이드바 FAB + 드로어 전환** (독립 검증 단위)
1. `SidebarFilters.vue` 마크업/스타일/접근성 로직 재작성.
2. `App.vue`의 `.page-body` 레이아웃 정리(플로우 영향 제거 확인).
3. 브라우저 검증(본 문서 4절 체크리스트 전반부) — **이 시점에 오너 확인을 받고** Phase 2로 진행.

**Phase 2 — 색상 체계 개편(안 B + 다크 토큰)** (독립 검증 단위)
1. `MonthlyComboChart.vue`에 `barColor` prop 도입.
2. `StatusDetailView.vue` 계약 콤보차트에 `barColor` 적용, 품의/집행 콤보차트는 판단 근거를 주석으로 남기고 변경하지 않음.
3. `DashboardView.vue`는 무변경 확인 + (선택) 근거 주석 추가.
4. `stageColors.ts` / `tokens.css`에 다크 토큰 값만 신규 정의(실제 스위치 배선은 이번 라운드 범위 밖).
5. 브라우저 검증(본 문서 4절 체크리스트 후반부).

두 Phase는 서로 되돌리기 쉽게 별개로 진행하며, Phase 1 완료·확인 전에는 Phase 2 파일을 건드리지 않는다.

## 2. 파일별 변경 계획

### 2-1. `frontend/src/components/layout/SidebarFilters.vue`
- 템플릿을 **2요소 구조**로 재편: `.filter-fab`(고정 원형 아이콘 버튼) + `.filter-drawer`(고정 오버레이 패널, `v-show="open"`). 필터 그룹 마크업(현재 L9~33, `sidebar-title`/`filter-group`/`filter-controls`/`option-list`/`selected-count`)은 그대로 드로어 내부로 옮기되 로직은 변경하지 않는다.
- FAB: 지름 40~44px 원형, 텍스트 라벨 없이 sliders/adjustments 아이콘(24px, `stroke: currentColor`, stroke-width 1.75) 인라인 SVG만 배치. 기본 상태 `background: var(--card-bg); border: 1px solid var(--border-color); box-shadow: 0 4px 12px rgba(15,23,42,0.10)`, hover 시 `translateY(-1px)` + 진한 그림자, 열림(active) 상태는 `background: var(--stage-po-soft); color: var(--stage-po-color); border-color: transparent`로 `App.vue`의 `.tab-btn.active`와 언어 통일.
- 좌표: 리뷰 문서 권장값 `top: 1.5rem; left: max(1rem, calc((100vw - 1660px) / 2 - 3.25rem))`을 1차 적용하되, 4절 검증에서 헤더 텍스트와 겹치는 것으로 확인되면 "구현 단순화 대안"(`top:1.25rem; left:1.25rem` 고정)으로 폴백 — 두 좌표안 중 최종 채택은 실측 후 결정.
- 활성 필터 개수 배지(선택, 권장 채택): 우상단 작은 원형 배지, `background: var(--stage-po-color); color:#fff; font-size:0.65rem`. **신규 계산 로직 필요** — 현재 `useFilters.ts`는 `loadMeta` 시 모든 그룹을 "전체 선택" 상태로 초기화하므로(L33~37) "전체 선택 = 필터 없음"이 기존 의미다. 배지 값은 "옵션 전체 개수 대비 해제된 옵션 총 개수"(또는 그룹 단위로 부분 선택된 그룹 수) 중 하나로 새로 정의해야 하며, 이 정의를 코드 작성 전에 확정한다.
- 오버레이 드로어: `position: fixed; top:0; left:0; width:264px; height:100vh; overflow-y:auto;` + `border-radius: 0 1rem 1rem 0;` + `box-shadow: 0 8px 30px rgba(15,23,42,0.16)`. 진입 `transform: translateX(-100%) → translateX(0)`, `220ms cubic-bezier(0.4,0,0.2,1)`. 헤더에 "공통 필터" 제목 + 닫기 `×` 버튼.
- 인터랙션: 클릭-아웃 닫힘(document 클릭 리스너로 패널 밖 판정), `Esc` 키 닫힘(window keydown), 모바일(<760px)에서만 반투명 스크림(`rgba(15,23,42,0.28)`) 표시.
- 접근성: FAB `aria-label="필터 열기"`, `aria-expanded`, `aria-controls`. 드로어 열릴 때 첫 포커스 이동 + 닫힐 때 트리거로 포커스 복귀. 완전한 Tab 순환 focus-trap을 자체 구현할지, 최소 구현(첫 포커스+Esc)만 할지는 3절 리스크에서 별도 판단.
- `@media (prefers-reduced-motion: reduce)`에서 슬라이드 트랜지션 비활성화.
- 제거 대상: `.sidebar`/`.collapsed`(L59~70) 폭 애니메이션, `.toggle-collapsed-label`(L92~94) 세로쓰기 스타일, 전폭 텍스트 토글 버튼 마크업(L3~6).
- `open` 모델(`defineModel`, 현재 L41)은 그대로 유지.

### 2-2. `frontend/src/App.vue`
- `.page-body`(L71~75)가 더 이상 사이드바 컬럼을 예약하지 않도록 정리. `<SidebarFilters v-model:open="sidebarOpen" />`(L13) 위치는 유지하되, 컴포넌트 내부가 전부 `position: fixed`이므로 flex 자식으로서 박스를 차지하지 않는지 1차로 그대로 두고 검증한다.
- **폴백 전략(2단계)**: 만약 검증 과정에서 `.page-body`의 `gap: 1.5rem`이 fixed 자식에도 여백을 만드는 현상이 관찰되면, `.page-body`를 `display:flex`에서 단순 블록으로 바꾸고 `.main-content`만 남기는 구조로 단순화한다. 또는 `SidebarFilters`를 `<Teleport to="body">`로 감싸 `.page-body`의 자식 목록 자체에서 제외하는 방법도 대안으로 검토(전역 CSS 변수는 `:root`에 선언되어 있어 teleport로 body 하위에 렌더링해도 스타일 상속에는 문제없음을 확인함).
- 그 외 App.vue의 헤더/탭/뷰 전환 로직은 변경하지 않는다.

### 2-3. `frontend/src/theme/stageColors.ts`
- 라이트 `STAGE` 상수(L6~13)는 그대로 유지.
- 다크값을 담을 신규 상수(예: `STAGE_DARK`)를 추가하되, **품의/계약/집행 3개 진한 색만** 정의(`poSoft` 등 소프트 값의 다크 버전은 리뷰 문서에 명시가 없어 이번 범위 밖으로 한정).
- 이 상수는 다크 프레젠테이션 모드(`/present` 라우트)가 아직 구현되어 있지 않으므로 **정의만 해두고 실제로 어디서도 참조되지 않는 상태**가 된다 — 주석으로 "다음 라운드에서 프레젠테이션 모드 도입 시 사용 예정"임을 명시한다.

### 2-4. `frontend/src/theme/tokens.css`
- 현재 다크 변수 세트가 전혀 없음을 재확인(0절 참고). `:root[data-theme="dark"] { --stage-po-color:#60A5FA; --stage-contract-color:#A78BFA; --stage-execution-color:#34D399; }` 형태의 **신규 선택자 블록만 추가**한다.
- 이번 라운드에서는 `data-theme="dark"`를 실제로 `<html>`/`<body>`에 설정하는 로직(라우터의 `/present` 진입, 테마 토글 등)을 구현하지 않는다 — 즉 **다크 토큰 값을 미리 정의해두는 수준으로 범위를 한정**하고, 실제 스위치 배선은 다음 라운드(프레젠테이션 모드 구현 시점)로 명시적으로 미룬다. 이 범위 한정은 오너 확인이 필요한 사항으로 별도 표시한다.
- `--stage-*` 값은 `stageColors.ts`의 `STAGE`/`STAGE_DARK`와 리터럴이 반드시 일치해야 하므로(파일 상단 주석 규칙과 동일 원칙을 다크값에도 적용), 두 파일을 같은 커밋에서 함께 수정한다.

### 2-5. `frontend/src/components/charts/MonthlyComboChart.vue`
- `defineProps`(L19~27)에 `barColor?: string` 추가.
- L57 `itemStyle: { color: '#E2E8F0' }`를 `itemStyle: { color: props.barColor ?? '#E2E8F0' }`로 변경. 미지정 시 기존 중립 회색이 유지되어 하위 호환 보장.
- 막대 라벨 색(`#475569`, L61)은 리뷰 문서 권장대로 유지(변경 없음) — soft 막대 위에서도 대비가 충분함.

### 2-6. `frontend/src/views/StatusDetailView.vue`
- **계약 상세 모니터링** "월별 누적 계약건수" 콤보차트(현재 코드 L124~148 부근)에 `:bar-color="STAGE.contractSoft"` 전달. 근거: 막대(`월별 계약건수`)와 라인1(`누적 계약건수`)이 **동일 지표(건수)의 월별/누적 관계**이므로 계약 색 계열로 통일하는 것이 리뷰 문서 원칙에 정확히 부합. 라인2(`누적 품의완료건수`, dashed, STAGE.po)는 다른 지표이므로 색 변경 없음.
- **품의 상세 모니터링** "월별 누적 품의금액" 콤보차트(L76~93 부근)를 직접 확인한 결과: 막대=`월별 투자건수`(건), 라인=`누적 품의금액`(금액) — **단위/지표가 서로 다름**(건수 vs 금액)이므로 리뷰 문서의 "동일 지표" 기준에 해당하지 않는다. → **변경하지 않음**(회색 유지). 코드에 판단 근거 주석을 남긴다.

## 3. 리스크/주의사항

1. **레이아웃 리플로우 검증 필요**: `.page-body`가 `display:flex`를 유지한 채 자식이 `position:fixed`로 바뀌었을 때 `gap`이 실제로 무시되는지는 사양상으로는 그렇지만 실제 렌더링에서 반드시 육안 확인 필요(2-2절 폴백 전략 참고).
2. **z-index 최초 도입**: 코드베이스 전체에 `z-index`가 한 곳도 없음을 확인했다(0절). FAB/드로어/스크림 3단 계층 값을 새로 정해야 하고, 기존 sticky 테이블 헤더(`DetailTable.vue` L97, `DiagnosisTable.vue` L52, `StageDetailTable.vue` L66 — 모두 z-index 미지정)보다 드로어가 항상 위에 뜨는지 스크롤 상태에서 확인이 필요하다.
3. **FAB와 헤더 텍스트 겹침 가능성**: `App.vue`의 `.page-header`는 fixed가 아니라 문서 흐름 최상단에 있고 `small-title`이 페이지 패딩(`2rem`) 부근에서 시작한다. FAB 좌표(`top:1.5rem`, `left`가 넓은 화면이 아닌 한 대부분 `max(...)`에 의해 `1rem`로 clamp됨)가 초기 로드 화면에서 헤더 상단부와 시각적으로 겹칠 가능성이 있어 실측 후 좌표 재조정이 필요할 수 있다.
4. **반응형 규칙이 이번이 최초**: 코드베이스 전체에 `@media` 쿼리가 하나도 없었다(0절). 드로어의 760px 스크림 브레이크포인트가 이 프로젝트의 첫 반응형 규칙이 되며, 다른 화면(6열 KPI 그리드, 상세 테이블 등)은 여전히 반응형 대응이 없으므로 좁은 화면에서 드로어만 스크림 처리되고 본문 레이아웃은 그대로 깨져 보일 수 있다 — 이번 라운드는 드로어 자체로 범위를 한정한다.
5. **focus-trap 구현 수준**: 라이브러리 없이 직접 구현 시 완전한 Tab 순환(포커스가 패널 밖으로 못 나가게)은 버그 여지가 있다. 최소 구현(열릴 때 첫 포커스 이동 + Esc 닫힘 + 닫힘 시 트리거로 포커스 복귀)까지만 이번 라운드에서 하고, 완전한 focus-trap은 필요 시 다음 라운드로 미루는 방안도 고려 대상으로 남긴다.
6. **활성 필터 배지 정의 오류 가능성**: `useFilters.ts`의 "전체 선택=필터 없음" 관례와 다르게 배지 로직을 정의하면 배지 숫자가 사용자 기대와 어긋날 수 있다 — 정의를 코드 작성 전 명확히 문서화할 것.
7. **`#E2E8F0` 하드코딩 잔존 지점**: `MonthlyComboChart.vue`(L57, 이번에 prop으로 대체)와 별개로 `StatusDetailView.vue` L172(`OrgStackedBarChart` 미집행 시리즈)에도 리터럴로 남아 있다(이번 범위 밖). 추후 다크 테마가 실제로 켜지는 라운드에서 이 리터럴이 다크 배경에서도 그대로 밝은 회색으로 남아 괜찮은지 재점검 필요.
8. **다크 토큰 "정의만 하고 미사용" 상태의 부작용**: `stageColors.ts`의 `STAGE_DARK`, `tokens.css`의 `:root[data-theme="dark"]` 블록이 실제로 아무 곳에서도 참조/적용되지 않으므로, 빌드 경고(미사용 export)나 "죽은 코드"로 오인될 수 있다 — 주석으로 목적을 명확히 남길 것.
9. **집행 상세 콤보차트의 barColor 적용 여부는 열린 결정**: 2-6절에서 "변경 없음"으로 판단했으나 이는 "막대·라인 단위가 다르다"는 엄격한 기준 적용 결과이며, 오너가 더 느슨한 기준(같은 집행 계열이면 색 통일)을 원할 수도 있어 재확인 여지를 남긴다.

## 4. 검증 방법(체크리스트)

- [ ] 데스크톱 와이드 화면(≥1660px)에서 FAB가 헤더/본문과 겹치지 않는지

- [ ] FAB 클릭 → 드로어 슬라이드-인 애니메이션 확인, **`.main-content` 폭이 전혀 변하지 않는지**(이번 개편의 핵심 목적) 확인
- [ ] 드로어 내부 필터 그룹/전체/해제/옵션 토글 동작이 기존과 동일한지(로직 변경 없음 재확인)

- [ ] 브라우저 콘솔에 새 에러/경고 없는지

## 5. 예상 소요

- **Phase 1 (사이드바 FAB/드로어)**: 보통. 필터 로직 자체는 재사용하지만 마크업 재구조화 + 접근성(포커스/Esc/클릭아웃) + 배지 계산 로직이 신규이고, 이 프로젝트 최초의 fixed/z-index/반응형 도입이라 검증 부담이 크다.
- **Phase 2 (색상 안 B + 다크 토큰)**: 간단. 건드리는 파일은 4개(`MonthlyComboChart.vue`, `StatusDetailView.vue`, `stageColors.ts`, `tokens.css`)지만 실질 변경량은 prop 1개 추가 + 호출부 속성 1곳 + 상수/토큰 블록 추가 수준으로 작다.
- **전체 체감**: 보통 — Phase 1이 볼륨의 대부분을 차지하고, Phase 2는 상대적으로 가볍다.
