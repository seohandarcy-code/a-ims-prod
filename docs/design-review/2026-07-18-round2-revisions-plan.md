## 1. "담당자" 헤더 줄바꿈 + 이름 줄바꿈 방지

### 현황
`DiagnosisTable.vue`(투자종합현황 "관리 우선순위" 표, 투자진행상세현황 "관리 필요 투자 진단" 표 공용)의 `<th>`/`<td>`에 `white-space: nowrap`이 없다. 이 표가 좁은 컬럼(`two-col` grid의 1fr 쪽)에 배치되다 보니 "담당자" 3글자 헤더가 "담당/자"로 줄바꿈되고, 담당자 이름 값도 동일한 이유로 줄바꿈될 수 있다(한글은 공백 없이도 글자 단위로 줄바꿈되는 게 기본 동작이라 브라우저가 임의 위치에서 끊는다).

같은 문제가 `StageDetailTable.vue`(상세현황 "건별 단계 진단 테이블")에도 동일하게 존재함을 확인했다(8행에 동일 `<th>담당자</th>`, 동일하게 nowrap 미지정).

### 수정 방향
- `DiagnosisTable.vue`: `조직`, `담당자` 두 컬럼의 `<th>`/`<td>`에 `white-space: nowrap` 적용(또는 `.simple-table th, .simple-table td`에 `word-break: keep-all` + 해당 두 컬럼만 `nowrap`). `진단내용`/`관리포인트`/`투자명`처럼 긴 텍스트가 들어가는 컬럼은 지금처럼 자연 줄바꿈을 유지해야 표 전체 폭이 과도하게 늘어나지 않는다.
- `StageDetailTable.vue`도 동일 원칙으로 같이 고칠지(요청엔 "투자종합현황"만 명시됐지만 동일 컴포넌트 패턴이라 같이 고치는 걸 권장) — **결정 필요**.

### 대상 파일
- `frontend/src/components/table/DiagnosisTable.vue`
- (선택) `frontend/src/components/table/StageDetailTable.vue`

### 예상 결과

## 2. 조직별 집행금액 차트를 InlineRatioBar 스타일로 통일

### 현황
- "조직별 품의완료 건수"(품의 상세)와 "조직별 계약건수"(계약 상세)는 `InlineRatioBar.vue`(직접 만든 CSS 기반 가로 바 — 라벨/트랙/채움/총계를 grid로 배치, 채움 안에 라벨 오버레이) 컴포넌트를 조직별로 반복 렌더링하는 방식.
- "조직별 집행금액"(집행 상세)만 `OrgStackedBarChart.vue`(ECharts 기반 가로 스택 막대, 집행금액/미집행 2개 시리즈)를 쓴다. 축/범례/그리드가 있는 정식 차트라 시각적으로 다른 두 개와 톤이 다르다.

### 수정 방향
`OrgStackedBarChart` 대신 `InlineRatioBar`를 재사용한다. 데이터 매핑: `label=조직명`, `filled=집행금액(억원 환산)`, `total=품의금액(억원 환산)`(또는 집행금액+미집행금액), `unit='억'`, `color=STAGE.execution`. 트랙의 채워지지 않은 부분이 자연스럽게 "미집행" 의미를 갖게 되어 별도 시리즈 없이도 품의/계약과 동일한 화법이 된다.

**구현상 확인 필요한 점**: `InlineRatioBar`는 현재 `filled.toLocaleString()`으로 정수 위주 표기(건수용으로 설계됨). 억원 단위 소수(예: 12.34억)를 그대로 넣으면 `toLocaleString()`이 소수 자리를 들쭉날쭉하게 표시할 수 있어, `InlineRatioBar`에 `decimals`(또는 포맷 함수) prop을 추가하는 작은 개선이 같이 필요하다.

### 대상 파일
- `frontend/src/views/StatusDetailView.vue` (집행 상세 모니터링의 "조직별 집행금액" 블록 — `OrgStackedBarChart` 호출을 `InlineRatioBar` 목록으로 교체)
- `frontend/src/components/charts/InlineRatioBar.vue` (소수 단위 표시 지원 추가)
- `OrgStackedBarChart.vue`는 다른 화면에서 쓰이지 않으면 이후 정리(삭제) 대상이 될 수 있음 — 이번엔 유지, 사용처 없어지면 다음 라운드에 정리.

### 예상 결과
투자진행 상세현황의 품의/계약/집행 3개 조직별 차트가 시각적으로 완전히 동일한 스타일(라벨-트랙-총계 가로 바)로 통일되어 탭을 전환해도 일관된 느낌을 준다.

### 난이도
보통(차트 교체 자체는 간단하지만 InlineRatioBar의 소수 표기 개선이 딸려 있음).

## 3~4. 월별 콤보차트 막대색 — "같은 지표" 원칙에서 "지표 고유색" 원칙으로 확장

### 현황 (지난 라운드 결정과의 관계)
지난 라운드(Phase 2)에서는 "막대와 라인이 같은 지표일 때만 막대에 단계색을 준다"는 원칙(안 B)으로 계약 상세만 `barColor`를 적용했다. 이번 요청은 그 원칙을 한 단계 더 확장한다 — **막대가 무엇을 나타내는 지표인지 자체로 색을 정한다**(라인과 같은 지표인지는 더 이상 조건이 아님). 즉:
- 월별 핵심 진행 흐름(종합현황)의 막대 = "월별 계약건수" → **계약 소프트 퍼플**(`STAGE.contractSoft`)
- 집행 상세 모니터링의 막대 = "월별 집행금액" → **집행 소프트 그린**(`STAGE.executionSoft`)
- 품의 상세 모니터링의 막대 = "월별 투자건수" → **품의 소프트 블루**(`STAGE.poSoft`)
- (기존 유지) 계약 상세 모니터링의 막대 = "월별 계약건수" → 계약 소프트 퍼플 (변경 없음, 이미 적용됨)

결과적으로 `MonthlyComboChart`를 쓰는 **4곳 전부**가 막대에 자기 지표에 맞는 단계색을 갖게 되어, 사실상 "언제는 회색 언제는 색"이라는 예외 규칙 자체가 없어지고 **기본값을 회색에서 각 화면의 주단계색으로 바꾸는** 쪽에 가까워진다. (지난 라운드에서 유지하기로 했던 "다른 지표면 회색" 근거는 이번 요청으로 대체됨 — 참고로 남겨둔 코드 주석들도 같이 정리 필요.)

### 수정 방향
- `MonthlyComboChart.vue`의 `barColor` prop은 이미 있으므로(Phase 2에서 추가됨) 재사용.
- 4개 호출부에 각각 해당 소프트 색을 명시적으로 전달:
  - `DashboardView.vue` "월별 핵심 진행 흐름" → `:bar-color="STAGE.contractSoft"`
  - `StatusDetailView.vue` 품의 상세 "월별 누적 품의금액" → `:bar-color="STAGE.poSoft"`
  - `StatusDetailView.vue` 집행 상세 "월별 누적 집행률" → `:bar-color="STAGE.executionSoft"`
  - `StatusDetailView.vue` 계약 상세 "월별 누적 계약건수" → 기존 유지
- 지난 라운드에 남긴 "왜 회색을 유지하는지" 판단 주석(`DashboardView.vue`, `StatusDetailView.vue` 품의/집행 블록)은 이번에 색이 바뀌므로 같이 삭제/수정.

### 대상 파일
- `frontend/src/views/DashboardView.vue`
- `frontend/src/views/StatusDetailView.vue`

### 예상 결과
4개 화면의 막대가 전부 옅은 단계색으로 바뀌어, 각 서브탭(품의/계약/집행)에 들어갔을 때 "지금 어떤 단계를 보고 있는지"가 막대 색만 봐도 즉시 인지된다. 라인은 기존처럼 진한 단계색(또는 다른 지표의 색)을 유지하므로 옅은 막대(배경) + 진한 라인(주인공)의 명도 위계도 그대로 살아있다.

### 난이도
간단(prop 값 4곳 추가/변경 수준).

## 5. KPI 메트릭 카드에 단계 상징색 반영

### 현황
`MiniKpiGrid.vue`의 카드는 `tone: 'normal' | 'good' | 'warn' | 'bad'` 값에 따라 **테두리 색만** 옅게 바뀐다(`--tone-good-border`/`--tone-warn-border`/`--tone-bad-border`). 이 tone은 **성과/위험 상태**(예: 집행률이 70% 이상이면 good, 관리필요 건수가 0보다 크면 bad)를 나타내는 용도로 쓰이고 있고, 지금은 3단계(품의/계약/집행) 색과는 무관하다. 반면 `StatusDetailView.vue`의 서브탭 버튼(`.sub-tab-btn.po/.contract/.execution`)에는 이미 활성 시 단계색을 채우는 패턴이 존재한다 — 이걸 KPI 카드에도 확장하자는 제안이다.

**핵심 쟁점**: 일부 카드는 이미 "성과 임계값에 따른 good/warn/bad"로 색이 정해져 있다(예: 품의완료율 80% 미만이면 warn, 관리필요 건수 0보다 크면 bad). 여기에 "품의=블루" 같은 고정 상징색을 얹으면 두 가지 색 신호(성과 상태 vs 단계 정체성)가 충돌한다. 그래서 **카드를 두 그룹으로 나눠 다르게 처리**하는 걸 제안한다:

- **A그룹 — 순수 집계/식별용 카드** (지금 성과 임계값이 없거나, 있어도 절대적 위험신호가 아닌 카드): 단계 상징색을 테두리에 적용.
- **B그룹 — 위험/백로그 지표 카드** (지연/대기/관리필요처럼 "0이면 좋고 늘어나면 나쁜" 카드): 기존 good/warn/bad 위험색 유지(이미 잘 동작 중이고, 이걸 상징색으로 덮으면 "위험한 상태"라는 신호가 사라짐).

**화면별 적용안**:

| 화면 | 카드 | 제안 | 근거 |
|---|---|---|---|
| 종합현황 | 전체 투자건수 | **검정(중립/총계)** | 특정 단계에 속하지 않는 전체 총량 |
| 종합현황 | 전체 투자금액 | **검정(중립/총계)** | 〃 |
| 종합현황 | 품의완료율 | **품의 블루** | A그룹 — 단일 단계 식별 지표 |
| 종합현황 | 계약전환율 | **계약 퍼플** | A그룹 |
| 종합현황 | 금액 집행률 | **집행 그린** | A그룹 |
| 종합현황 | 관리필요 건수 | 기존 유지(빨강) | B그룹, 변경 없음(요청 예시 그대로) |
| 상세현황 상단 | 품의완료율 | **품의 블루** | A그룹 |
| 상세현황 상단 | 품의→계약 전환율 | **계약 퍼플** | A그룹(어느 단계로 "들어가는" 지표인지 기준) |
| 상세현황 상단 | 계약→집행 발생률 | **집행 그린** | A그룹 |
| 상세현황 상단 | 금액 기준 집행률 | **집행 그린** | A그룹 |
| 상세현황 상단 | 품의 지연 / 계약 대기 / 집행 대기 | 기존 유지(위험색) | B그룹, 변경 없음 |
| 상세현황 상단 | 잔여 집행금액 | **열린 결정** | 위험지표로 볼지 집행계열 식별지표로 볼지 애매 — 오너 판단 필요 |
| 품의/계약/집행 상세 서브탭 내부 KPI(3~4장씩) | 순수 집계 카드(대상건수/완료건수/등록건수/품의금액/기성처리금액 등) | **해당 탭의 상징색** | 이미 서브탭 자체가 색으로 구분되니 카드도 통일하면 탭 전환 시 색 일관성 강화 |
| 〃 | 전환율/집행률 등 임계값 카드 | 기존 유지(위험색) | B그룹 |

### 구현 방식
`MiniKpiGrid.vue`의 `tone` 옵션에 `'po' | 'contract' | 'execution' | 'total'` 4개를 추가하고, CSS에 `.tone-po { border-color: var(--stage-po-color) }` 식으로 매핑(불투명도 낮춘 톤 사용 권장 — 기존 good/warn/bad와 시각적 무게 맞추기 위해 `--stage-*-soft`를 border-color로 쓰거나, border만 살짝 진하게 하고 배경은 그대로 흰색 유지). "검정(총계)"는 `--text-main` 또는 신규 `--tone-total-border` 토큰(예: `rgba(15,23,42,0.35)`)으로 정의.

### 대상 파일
- `frontend/src/components/kpi/MiniKpiGrid.vue` (tone 옵션 확장 + CSS)
- `frontend/src/views/DashboardView.vue` (kpiCards의 tone 값 재지정)
- `frontend/src/views/StatusDetailView.vue` (overviewCards/poCards/contractCards/executionCards의 tone 값 재지정)

### 예상 결과
어느 화면에 있든 "이 숫자가 품의/계약/집행 중 무엇과 관련 있는지"가 카드 테두리 색만 봐도 바로 인지되고, 진짜 "주의가 필요한" 지표(위험색)와 "그냥 현재 단계를 보여주는" 지표(상징색)가 시각적으로 구분된다.

### 열린 결정 사항 (실행 전 확인 필요)
1. "잔여 집행금액" 카드를 위험색으로 볼지, 집행 상징색으로 볼지.
2. B그룹(위험색 유지 카드)에도 아주 약하게 상징색을 곁들일지(예: 왼쪽 4px 굵은 라인만 상징색, 테두리 전체는 기존 위험색 유지), 아니면 이번 요청대로 완전히 손대지 않을지.
3. "총계(검정)" 카드를 테두리색만 바꿀지, 아니면 라벨/숫자 텍스트에도 약간의 강조(굵기·크기)를 추가해 다른 색상 카드들 사이에서 도드라지게 할지.

### 난이도
보통(컴포넌트 옵션 확장 + 여러 화면의 카드 배열 수정, 실질 코드량은 적지만 화면별로 하나씩 확인해야 함).

## 종합 실행 순서 제안
