# 역할

"팀 투자 관리 시스템" 프론트엔드(`frontend/`) 담당. Vue 3 + TypeScript + Composition API(`<script setup>`)를 사용하고, 상태관리는 Pinia, 라우팅은 Vue Router, 차트는 ECharts, UI 컴포넌트는 Element Plus 또는 naive-ui를 사용한다.

## 디자인 시스템
- 단계별 색상 코드: 품의=블루, 계약=퍼플, 집행=그린을 모든 관련 요소(퍼널 카드, 리스트바, 콤보차트)에 일관되게 적용한다.
- 라이트(업무용) 테마와 다크(프레젠테이션용, `/present` 라우트) 테마를 이중으로 유지한다. 프레젠테이션 모드는 초대형 폰트/두꺼운 라인으로 원거리에서도 읽히게 한다.
- 신규 컴포넌트 우선순위: `StageFunnelCard`(단계 전환율 카드), `InlineRatioBar`(조직별 인라인 리스트바), `CumulativeComboChart`(월별 막대+누적라인+끝점 콜아웃), `PresentationBigStat`/`PresentationBarBoard`(프레젠테이션 모드 전용).

## 인증 UI
- 일반 사용자는 로그인 없이 전체 조회만 가능하다.
- 사이드바 필터 최하단에 눈에 띄지 않는 스타일의 "관리자 로그인" 링크만 둔다(평상시엔 존재감 없이).
- 로그인 성공 시에만 상세 테이블의 편집 아이콘과 관리자 화면(`/admin`) 메뉴가 노출된다.

## API 연동
- API 주소를 하드코딩하지 않는다. 빌드 시점이 아니라 런타임에 환경변수를 주입하는 방식(예: 컨테이너 시작 시 `config.js`를 치환)을 사용해, 환경(Dev/Staging/Prod)별로 이미지를 다시 빌드하지 않아도 되게 한다.

# 이 프로젝트에서 절대 하면 안 되는 것

- **일반 사용자 화면에 편집 관련 UI 노출 금지**: 연필/자물쇠 아이콘, 편집 패널 진입점 등은 로그인한 관리자에게만 보여야 한다. 1단계는 "관리자 전용 편집"이 확정 범위이며, 담당자별 편집 UI(자물쇠/연필 분기)는 아직 만들지 않는다.
- **관리자 진입점을 눈에 띄게 만들지 말 것**: "관리자 로그인"은 사이드바 필터 하단에 작은 텍스트 링크로만 존재해야 한다. 헤더 상단에 큰 로그인 버튼을 만드는 등 눈에 띄게 배치하지 않는다.
- **API 주소 하드코딩 금지**: `http://localhost:8000` 같은 값을 소스에 박아 넣지 않는다.
- **인증 로직을 프론트에서 직접 판단하지 말 것**: 편집 가능 여부는 항상 백엔드 응답(`editable` 등)을 기준으로 표시만 한다 — 프론트에서 자체적으로 권한을 계산해 편집 UI를 노출하지 않는다.
- **SSO 연동 UI를 미리 활성화하지 말 것**: 관리자 화면의 SSO 설정 섹션은 "추후 지원 예정" 비활성 상태로만 둔다. 실제 SSO 연동 전까지 활성화된 것처럼 보이게 만들지 않는다.
