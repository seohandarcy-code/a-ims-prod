## 4. 컬럼 간 의존관계 / 파생 로직 (목업 데이터 생성 규칙)

**중요:** 아래는 이번에 생성한 **목업 데이터 규칙**입니다. 실데이터 연동 시 동일한 업무 로직이 적용될 가능성이 높으므로, 백엔드 검증/계산 로직 설계 시 참고하세요.

### 4.1 심의완료 판정 (선행 조건)
```
심의완료 = (팀장심의_의견 == '승인')
           AND (센터장_심의필요 == '불필요' OR 센터장_심의의견 == '승인')
```
심의완료 건에 한해서만 `ERP등록` 또는 `IRB심의` 경로가 진행됩니다. (34건 중 21건 해당)

### 4.2 ERP / IRB 배타 경로
- 심의완료 건은 **ERP등록 경로** 또는 **IRB심의 경로** 중 하나만 가집니다 (동시에 둘 다 진행되지 않음).
- 목업 데이터에서는 약 3:7 비율로 배정(ERP 6건 / IRB 15건).

### 4.3 단계별 진행 (funnel 구조)
```
IRB심의 완료  →  IT-PMS 완료  →  계약월_입력 / 계약금액_입력 값 존재
```
- `IRB심의`가 값이 있어야 `IT-PMS`가 진행될 수 있음
- `IT-PMS`가 `완료`여야 `계약월_입력` / `계약금액_입력`이 채워질 수 있음
- 각 단계는 항상 다음 단계로 이어지지 않고, 일부는 빈값(미완료)으로 남을 수 있음 → 프론트/백엔드는 이 컬럼들을 **nullable**로 취급해야 함

### 4.4 계약완료구분
```
계약완료구분 = '완료'  if (ERP등록 == '등록') OR (계약월_입력 값 존재)
             else 빈값
```

### 4.5 실행품의금액
```
if ERP등록 == '등록':
    실행품의금액 = 투자비 값
elif 계약월_입력 값 존재:
    실행품의금액 = 계약금액_입력 값
else:
    실행품의금액 = 빈값
```

## 5. 투자완료 판정 및 기성(집행) 데이터 정합성 수정

### 5.1 문제 배경
최초 신규 컬럼 추가 시, `기성단계`/`기성_월`/`기성_금액`/`기성_월_예측`/`기성_금액_예측`/`기성처리금액_합계`(이하 "기성 데이터")는 **원본 `raw_dt.dat`에 이미 존재하던 값**(기본품의금액 기준으로 생성)을 그대로 유지했습니다. 반면 `실행품의금액`은 이번에 새로 만든 개념(투자비 또는 계약금액_입력 기준)이라, 두 데이터가 서로 다른 기준으로 독립 생성되어 있었습니다. 그 결과:
- `계약완료구분=완료`인 건도 `실행품의금액 ≠ 기성처리금액_합계`가 되어 "투자완료"를 판정할 방법이 없었음
- `계약완료구분`이 빈값(계약 미완료)인데도 기성 실적이 이미 잡혀 있는 건이 존재 → "심의 → 품의 → 계약 → 기성집행 → 투자완료" 순서에 어긋남

### 5.2 수정 로직
**(1) 계약 미완료 건 초기화**
```
계약완료구분 != '완료' 이면서 기존 기성처리금액_합계 > 0 인 행은
기성단계 / 기성_월 / 기성_금액 / 기성_월_예측 / 기성_금액_예측 / 기성처리금액_합계 를
모두 공백으로 초기화 (계약 전이므로 집행 없음)
```

**(2) 계약완료 건의 기성 데이터 재계산**
`계약완료구분=완료`인 건들을 무작위로 약 30%(즉시완료) / 70%(진행중)로 나눠 재계산합니다.

- **즉시완료 그룹**: 기존 기성단계(실적+예측 전체)를 하나의 "완료된 실적"으로 병합, 각 단계 금액을 `실행품의금액`에 비례 배분 → `기성_월_예측`/`기성_금액_예측`은 공백 → `기성처리금액_합계 = 실행품의금액`
- **진행중 그룹**:
  - 기존에 예측 단계가 있던 건: 실적/예측 비율을 유지한 채 전체 합이 `실행품의금액`이 되도록 비례 스케일링, `기성처리금액_합계`는 스케일링된 실적분만 반영
  - 기존에 예측 단계가 없던 건: 기존 `기성_금액`(실적)은 그대로 두고, 새 예측 단계 1개를 추가해 `실행품의금액 - 기존 기성_금액`을 `기성_금액_예측`에 채움

### 5.3 투자완료 컬럼 로직
```
투자완료 = '완료'  if (실행품의금액 값 존재) AND (실행품의금액 == 기성처리금액_합계)
         else 빈값
```

## 6. 기준월(9월) 타임라인 정합성 보정 (`_rev`)

### 6.1 문제 배경
5번 항목의 재계산 로직을 적용한 직후, **현재 기준월을 9월로 볼 때 아직 오지 않은 미래 시점이 "이미 실적(완료)"으로 기록된 3건**이 발견되었습니다.

| NO | 위치 | 수정 전 값 | 문제 |
|---|---|---|---|
| 12 | 기성_월(실적) | `6월/11월` | 11월(미래)이 이미 지급된 것으로 기록됨 |
| 31 | 기성_월(실적) | `1월/11월/12월` | 11월·12월(미래)이 이미 지급된 것으로 기록됨 |
| 18 | 계약월_입력 | `11월` | 계약완료구분=완료인데 계약월이 미래 시점 |

원인은 5번의 "즉시완료" 병합 로직이 원래 남아있던 예측 단계를 미래 여부 확인 없이 실적으로 합쳐버린 것과, 계약월 생성 로직이 심의진행_월=9월(기준월과 동일)인 경계 케이스에서 미래월이 나올 수 있음을 놓친 것입니다. (원본 `raw_dt.dat`의 심의진행_월/계약_월 등 기존 컬럼은 전수 점검 결과 이상 없었습니다.)

### 6.2 수정 로직

**NO12, NO31 — "즉시완료" → "진행중"으로 재분류**
- 기준월(9월) 이전 실적만 `기성_금액`/`기성_월`에 남기고, 기준월 이후 금액은 `기성_월_예측`/`기성_금액_예측`으로 되돌림
  - NO12: 실적 `6월 / 68,570,000` 유지, 예측 `11월 / 205,730,000`으로 이동
  - NO31: 실적 `1월 / 120,000,000` 유지, 예측 `11월·12월 / 180,000,000·180,000,000`으로 이동
- `기성처리금액_합계` = 실적분만 재계산 (NO12=68,570,000 / NO31=120,000,000)
- `투자완료` = 공백으로 변경

**NO18 — 계약완료 취소, "계약 진행중" 상태로 롤백**
- 심의가 9월(기준월)에 막 끝난 건이 같은 달에 계약까지 끝나는 것은 비현실적이므로, 아직 계약이 체결되지 않은 것으로 재분류
- `계약월_입력` / `계약금액_입력` / `계약완료구분` / `실행품의금액` / `투자완료`를 공백으로, `기성단계` ~ `기성처리금액_합계`도 5.2절 (1)과 동일하게 전부 공백으로 초기화

### 6.4 프론트/백엔드 유의사항
- 데이터에 등장하는 모든 "실적(이미 발생한 것으로 표시되는 값)"은 기준월(9월) 이하 월에만 존재합니다. 화면에 "기준월" 개념을 노출한다면(예: 대시보드 상단 "2026년 9월 기준") 이 데이터와 정합됩니다.
- 실데이터 연동 시, 백엔드에서 기성 실적을 입력/수정하는 화면이 있다면 **입력 월이 현재 기준월보다 미래일 수 없도록** 검증 로직을 넣는 것을 권장합니다 (이번에 발견된 문제와 동일한 유형의 데이터 오류를 실운영에서도 예방).
- `기성단계`가 재계산 과정에서 원래보다 단계 수가 늘어난 행이 있습니다. 프론트에서 `기성단계`/`기성_월`/`기성_금액`을 `/` 기준으로 파싱해 리스트로 매핑하는 로직이 있다면 단계 수 변화에 영향받지 않는지 확인 필요
- `투자완료` 배지는 `계약완료구분=완료` 배지와 별개로 표시해야 합니다 (계약완료 ≠ 투자완료, 계약완료는 계약 체결 완료, 투자완료는 집행까지 100% 끝난 상태)

## 8. 프론트/백엔드 반영 시 체크리스트

- [ ] `조직` → `PJT` 컬럼명 변경에 따른 API 스키마/모델 필드명 업데이트
- [ ] 신규 10개 컬럼(파트 제외 시 9개 + 투자완료)을 백엔드 데이터 모델(FastAPI Pydantic 스키마 등)에 추가
- [ ] `ERP등록` / `IRB심의` / `IT-PMS` / `계약완료구분` / `투자완료`는 값이 있을 때만 `완료`류 배지로 표시하고, 빈값은 "미진행" 등으로 프론트에서 처리
- [ ] `계약월_입력` / `계약금액_입력` / `실행품의금액`은 숫자·월 문자열이 비어있을 수 있으므로 nullable 처리 및 숫자 포맷팅(₩ 표시 등) 필요
- [ ] `파트` 드롭다운/필터 UI 추가 시 7번 매핑표 기준으로 PJT 종속 옵션 구성
- [ ] 목업 데이터의 ERP/IRB 배타 관계, funnel 진행 로직(4번), 기성 데이터 재계산 로직(5번), 타임라인 정합성 보정(6번)은 실데이터 연동 전까지는 화면상 참고용이며, 실제 업무 규칙 확정 시 재검토 필요
- [ ] 투자 진행 단계 표시 UI(예: 스텝바)를 만든다면 "심의완료 → 계약완료 → 기성집행중 → 투자완료" 4단계로 구성하는 것을 권장 (6.3 분포표 참고)
- [ ] "기준월"을 화면에 파라미터로 노출할지 검토 (현재는 9월로 고정된 목업 기준)
